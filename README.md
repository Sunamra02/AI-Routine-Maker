# AI Routine Maker

A full-stack web app that helps people build structured daily routines with the help of AI. Instead of figuring out a routine from scratch, the user describes their goals and the app generates personalized routine suggestions - complete with tasks, timings, and priorities - which can then be saved, edited, and tracked over time.

See the [Project Setup Guide](#project-setup-guide) for installation and configuration instructions.

## How It Works

The app follows a simple flow:

- **Sign up / Log in** - user accounts are created and sessions are managed server-side with HTTP-only cookies.
- **Create a Routine** - the user fills in details about their goals, and the AI generates multiple routine suggestions to choose from.
- **Customize & Save** - the user picks a suggestion, edits tasks if needed, and saves the routine.
- **Track Progress** - saved routines can be viewed day by day, tasks can be marked as complete, and overall progress is visible on a dedicated page.

## Tech Stack

### Frontend

The frontend is built with **React 19** using **Vite** as the build tool and dev server. Routing is handled by **React Router v7**, and the UI is styled with **Tailwind CSS v4**. Icons come from **Font Awesome**. All API calls to the backend go through a centralized service layer using the native `fetch` API with session cookies for authentication.

- **React 19** - component-based UI
- **Vite** - fast dev server and bundler
- **React Router v7** - client-side routing (Home, Create, My Routines, Progress, Login, Edit, Routine Detail)
- **Tailwind CSS v4** - utility-first styling
- **Font Awesome** - icons

### Backend

The backend is a **Spring Boot 4** REST API written in **Java 17**. It handles authentication, routine management, and communication with the AI API. Spring Data JPA with Hibernate is used as the ORM to interact with the database. Passwords are hashed using **BCrypt** via Spring Security Crypto. Jackson handles JSON parsing for the AI response payloads.

- **Spring Boot 4 (Spring MVC)** - REST API framework
- **Spring Data JPA + Hibernate** - ORM and database access
- **Spring Security Crypto (BCrypt)** - password hashing
- **Spring Session** - server-side session management with HTTP-only cookies
- **Lombok** - boilerplate reduction
- **Jackson Databind** - JSON parsing for AI API responses
- **Spring Boot Actuator** - health and monitoring endpoints

### AI - Groq API

Routine suggestions are generated by calling the **Groq API**, using the **`llama-3.3-70b-versatile`** model. The backend sends the user's input as a structured prompt and parses the returned JSON to extract routine and task suggestions. The frontend never talks to Groq directly - everything goes through the backend.

### Database - MySQL

User data, routines, and task completion states are all stored in a **MySQL** database. The schema is managed automatically by Hibernate (`ddl-auto=update`), so no manual migrations are needed during development.

# Prerequisites

The following software must be installed before running the project:

- Node.js and npm
- Java JDK 17
- MySQL Server

The backend uses MySQL as its database, so MySQL must be installed and configured before the server is started.

---

# 1. Configure MySQL

**MySQL must be installed and configured properly before running the server.**

### Step 1: Open MySQL

Log in to the MySQL server using a MySQL client.

### Step 2: Create a database

Create a database using the following command:

```sql
CREATE DATABASE ai_routine_maker;
```

Use a lowercase database name for better compatibility.

---

# 2. Configure the Groq API

The server uses the Groq API, so a Groq API key must be created and stored as an environment variable before starting the server.

### Step 1: Create a Groq account

Create an account at:

[https://console.groq.com/home](https://console.groq.com/home)

### Step 2: Create an API key

Open:

[https://console.groq.com/keys](https://console.groq.com/keys)

Create a new API key.

### Step 3: Set the API key as an environment variable

Create an environment variable named:

```text
GROQ_API_KEY
```

Set its value to the Groq API key.

### Note

- The environment variable must be named as shown above; otherwise, the application will not work correctly.
- Do not commit the API key to the GitHub repository.

---

# 3. Configure the Server for Database

The server contains the Spring Boot backend.

### Step 1: Open `application.properties`

Open the following file:

```text
server/src/main/resources/application.properties
```

### Step 2: Configure the database URL

Find:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/******
```

Replace `******` with the database name created in MySQL.

For example, if the database was created with:

```sql
CREATE DATABASE ai_routine_maker;
```

change the property to:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/ai_routine_maker
```

### Step 3: Configure the MySQL password

Create an environment variable named:

```text
MYSQL_DB_PASSWORD
```

Set its value to the password of the MySQL user.

The `application.properties` file must contain:

```properties
spring.datasource.password=${MYSQL_DB_PASSWORD}
```

This keeps the MySQL password out of the project files.

### Note

- The environment variable must be named as shown above; otherwise, the application will not work correctly.
- Do not commit the MySQL password to the GitHub repository.

---

# 4. Run the Server

### Step 1: Open a terminal in the project root

Change to the `server` directory:

```bash
cd server
```

### Step 2: Start the Spring Boot application

On Windows Command Prompt, run:

```cmd
mvnw.cmd spring-boot:run
```

On Windows PowerShell, run:

```cmd
.\mvnw.cmd spring-boot:run
```

The Maven Wrapper runs the Spring Boot application without requiring a separate Maven installation.

The application can be used after Spring Boot has finished starting.

---

# 5. Run the Client

### Step 1: Open a terminal in the project root

Change to the `client` directory:

```bash
cd client
```

### Step 2: Install dependencies

Run:

```bash
npm i
```

This installs the dependencies required by the React application.

### Step 3: Start the development server

Run:

```bash
npm run dev
```

Vite starts the frontend at:

```text
http://localhost:5173
```

The application is available at this address in a browser.

## Run the Application from Next Time

#### After the initial setup is complete once, the application can be started anytime using the following commands.

### Terminal 1 - Server

```cmd
cd server
.\mvnw.cmd spring-boot:run
```

Wait for Spring Boot to finish starting.

### Terminal 2 - Client

```cmd
cd client
npm run dev
```

The frontend is available at:

```text
http://localhost:5173
```

Both the server and client must be running for the complete application to operate.
